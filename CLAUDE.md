# CLAUDE.md

Hackathon project: BattleVerse 2026 (Iqra University), Battle of Intelligence, Pillar 5 (Greenwashing & Disclosure Verification).
The system checks a coal power company's two green claims, its emissions and its tree offsets, against satellite evidence, and refuses to answer when inputs or evidence are not good enough.

Read before working:
- Design spec: `docs/specs/2026-11-11-green-claims-verification-design.md` (source of truth for rules, codes, files)
- Build plan: `docs/plans/2026-11-11-build-plan.md` (task order; tick boxes as you go)
- Plain-language pitch and jury Q&A: `docs/PITCH_BRIEF.md`

## Commands

```bash
pip install -r requirements.txt
python -m pytest                 # all tests
python -m pytest tests/test_guard.py -v   # C04 guard cases
python -m verify.build           # rebuild every output from data/ into outputs/
streamlit run app/streamlit_app.py
```

## Layout

- `verify/`: Python package, all logic. `rules.py` holds every threshold and bound; change numbers there, nowhere else.
- `gee/`: Earth Engine Code Editor scripts. Run by a team member in their own account; outputs are committed to `data/raw/`. Python never calls Earth Engine.
- `data/manual/`: hand-entered CSVs (sites, NEPRA, claims, plots, assumptions). Each row cites its source.
- `data/raw/`: downloaded or exported data, never edited by hand.
- `data/synthetic/`: generated test data. Every row has `data_flags` containing `synthetic`.
- `outputs/`: generated by `verify.build`. Do not hand-edit.
- `app/`: Streamlit app (`streamlit_app.py` page, `charts.py` charts and the 3D map), reads `outputs/` only. Visual rules live in `DESIGN.md`; follow it for any UI change.
- `scripts/`: one-off data fetchers (Earth Engine exports, Climate TRACE). The only code allowed to touch the network. `export_trees.py` saves C07 samples in batches and resumes after an interruption.

## Rules

**Commits and attribution**
- No AI attribution anywhere: no `Co-Authored-By` trailers, no "Generated with" lines, no mention of Claude or Anthropic in commits, PRs, code comments or docs. Commits are authored by the team member's own git identity.
- Commit only when asked. Never commit to the Shajar repo (`../Shajar`); it is read-only reference.

**Domain honesty (these are scored by the jury)**
- The satellite measures NO2, not CO2. CO2 is always a range, labelled "derived, not measured".
- Never use these words in UI text or docs meant for the jury: fraud, breach, proves, zero carbon, net zero.
- Never claim "1 km resolution". The Earth Engine grid is ~1.1 km; the sensor footprint is several km.
- Every synthetic or invented value is visibly labelled in file names, `data_flags`, charts and the app.
- INCONSISTENT means "refer for review", not "the company lied".

**Validation gate (C04)**
- Every request returns exactly one record with status `OK`, `LOW_CONFIDENCE` or `REJECTED`. Never a confident number for an impossible or unsupported input.
- REJECTED: no estimate computed or shown. LOW_CONFIDENCE: estimate shown greyed, verdict may only be `CANNOT_VERIFY`.
- Small negative NO2 (above −0.001 mol/m²) is normal sensor noise and passes. Do not filter it.
- Reason codes are fixed in the spec §8. Add a new code to the spec before using it in code.

**Demo safety**
- The app and the build never call a live API. All external data is fetched once by a script in `scripts/` and saved under `data/raw/`.
- `python -m verify.build` must work on a fresh clone with the committed data.

**Code style**
- Python 3.11+, pandas, scikit-learn, Streamlit, pytest. Keep dependencies to `requirements.txt`.
- Plain functions over classes. Small modules. No speculative abstraction; this is a 3-day build.
- Test-first for `gate`, `verdict`, `claims` and `trees`: these are what the jury tests live.
- Messages shown to users are one plain sentence a banker can read without a glossary.
